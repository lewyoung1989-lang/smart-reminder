# 药盒照片缩略图与识别触发设计

## 目标

药盒录入采用“先拍照、再核对、最后识别”的明确流程。用户拍完照片后先在当前页面看到缩略图，确认照片正确后主动点击“开始识别”。拍照动作本身不得上传图片或创建 OCR 任务。

本阶段只调整 Flutter 端药盒识别页面的拍照预览与状态边界，不修改 OCR API、MinIO 保存策略、识别模型、药品入库字段或服务端任务状态。

## 页面交互

拍照区使用已确认的 A 双缩略图方案：

- 药盒正面为必拍项，有效期为可选项。
- 未拍摄时，每个位置显示对应的拍摄入口。
- 拍摄成功后，入口原位变为 `4:3` 缩略图，图片使用内存字节渲染，不新增本地持久文件。
- 缩略图右上角提供重拍图标按钮；按钮有“重新拍摄药盒正面”或“重新拍摄有效期”的语义标签。
- 正面照片存在后，“开始识别”按钮启用；只有有效期照片而没有正面照片时仍保持禁用。
- 用户点击“开始识别”后，才调用现有 `createJob`，依次进入上传、处理中和结果核对状态。

缩略图区域使用稳定的尺寸约束，照片加载、重拍或错误提示不得引起按钮位置明显跳动。图片使用 `BoxFit.cover` 填充，页面不展示原始文件名或存储地址。

## 状态与数据流

页面继续持有 `_frontBytes` 和 `_expiryBytes` 两份内存数据，不新增独立持久状态。数据流为：

```text
未拍摄 -> 打开相机 -> 返回图片字节 -> 本地缩略图
本地缩略图 -> 点击开始识别 -> 上传图片 -> 创建并轮询 OCR 任务
OCR 成功 -> 核对候选 -> 确认入库 -> 清空图片和任务状态
```

重拍成功时只替换对应图片；用户取消重拍时保留原缩略图。用户尚未点击“开始识别”就离开页面时，内存图片随页面销毁，不产生服务端上传记录。

## 错误恢复

- 相机权限或调用失败：保留已有缩略图，并显示现有相机错误提示。
- 用户取消拍照或重拍：不显示错误，不清除已有缩略图。
- 上传失败：回到预览状态并保留两张图片，用户可直接重试或重拍。
- OCR 失败或轮询超时：回到预览状态并保留图片，继续显示对应错误提示。
- 确认入库成功：清空图片、OCR 任务和错误状态，回到初始拍摄状态。

## 测试与验收

Flutter Widget 测试覆盖：

- 初始状态没有缩略图，“开始识别”不可点击。
- 拍摄正面后显示正面缩略图与重拍按钮，但尚未调用 `createJob`。
- 拍摄可选有效期后同时显示两张缩略图。
- 点击“开始识别”时只调用一次 `createJob`，并传入当前两张图片字节。
- 取消重拍保留旧缩略图；重拍成功替换旧图片。
- 上传、识别失败或超时后仍显示缩略图并可重试。
- 确认入库后缩略图消失，页面恢复初始状态。

真机验收使用签名 Release 包：拍摄药盒正面后确认页面显示缩略图，未点击按钮前服务器没有新的 OCR 上传；点击“开始识别”后服务器才出现上传和任务请求，并能进入结果核对页面。
