# iOS HIG 界面重设计

## 目标

将智能提醒 iPhone 客户端调整为符合 Apple Human Interface Guidelines 的高频工具界面：以底部标签、系统化导航层级、分组列表、上下文权限和无障碍优先为基础，同时保留真实库存/OCR、认证和提醒确认能力。

## 适用范围

以 iPhone 为第一目标，覆盖 375pt 至 430pt 宽度、横屏、深色模式和最大 Dynamic Type。iPad 保持可用的自适应分栏，不为其单独建立桌面信息架构。

## 导航

底部 Tab Bar 固定保留三个顶层目的地：今天、计划、药箱。选中标签使用填充图标，未选中使用轮廓图标。详情采用标准路由推进与系统左缘返回手势，不通过自定义拖拽或抽屉导航替代。

顶层页面使用大标题；滚动后自然呈现紧凑标题。设置从导航栏齿轮进入，承载主题、个人资料、修改密码和退出登录，不作为第四个标签。

## 页面与组件

今天、计划和药箱使用 iOS 风格的 inset grouped 信息分组：同类操作放在一个带系统分隔的组中，行高至少 44pt。状态以图标、文字和语义色共同表达，不能只用颜色。

药箱使用系统搜索位置和筛选器。药品详情是独立层级页面，批次、有效期和数量以分组行展示。删除使用可见的删除按钮或标准尾部滑动操作，且必须弹出确认警告。

快速创建和 OCR 是带取消入口的单层底部 Sheet；不堆叠 Sheet。解析、上传、轮询和确认等等待状态在原位置内显示进度，不能以全屏阻塞转圈替代内容。

## 触控、权限与反馈

所有可交互元素命中区域至少为 44x44pt，主要确认动作位于底部安全区和拇指可达区域。相机权限仅在用户点击拍照录入后说明用途并请求；永久拒绝时提供打开系统设置的操作。OCR 候选确认前不写入库存。

异步操作立刻给出禁用、进度或文本反馈；成功、警告和失败都使用不依赖颜色的文字提示。重要的创建、确认和删除可在真机阶段加入系统触感反馈。

## 字体、颜色与无障碍

使用 Flutter 语义文本样式并允许文字缩放；自定义中文字体按文本比例缩放。页面必须通过 200% 文本比例、深色模式、VoiceOver 标签、Android/iOS 等价点击目标和对比度测试。交互色仅使用深绿色，错误、警告和成功使用明确语义色及图标。

## 验收

- 顶层仅保留今天、计划、药箱三个标签，并保持状态。
- 主页面、详情、Sheet 和权限入口均不遮挡安全区。
- 所有动作具有 44pt 命中区、可读的语义标签和非颜色状态提示。
- 在 375pt、430pt、横屏和 200% 文本比例下无溢出，主要操作可触达。
- 深色模式、真实药箱/OCR、认证、提醒确认和通知重试行为保持正确。
