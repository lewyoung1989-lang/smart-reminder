## 产品定位

这是一个“智能提醒 App”，不是泛化聊天助手。

V1 的核心思路是：

- 模型负责理解用户自然语言，生成结构化草稿。
- 系统只执行经过验证的工作流组件。
- 用户确认前不创建正式提醒。
- 新类型首次确认；用户信任后，同类请求未来可减少确认。

当前已经优先做的是 A+C 路线：

- A：明确语义提醒，例如“明天晚上 8 点提醒我洗澡”。
- C：固定且可验证的工作流组件，例如吃药、药品有效期、出门提醒、今日行动中心。

未来计划是 B+C：

- B：更主动的智能助手能力，例如根据日程、天气、交通自动生成提醒建议。
- C：仍然通过受控工作流执行，避免模型直接操作系统或外部服务。

V2 方向写在：

```text
docs/superpowers/specs/2026-08-05-smart-reminder-v2-enhancements.md
```

### 模型优先的文字与语音理解

- 支持输入中文自然语言或使用语音转写文本创建提醒草稿。
- 配置 DeepSeek 后，统一由模型优先判断为单次提醒或已注册工作流；失败时才回退本地规则。
- 模型输出只能是严格校验的 `ReminderDraftData` 或 `TaskSpec`。
- 模型不能生成工作流节点、URL、代码、数据库动作或权限字段。
- 系统只用 `WorkflowCompiler` 从注册模板编译工作流，并核对模型提示与最终模板一致。
- 模型输出会经过 Pydantic 严格校验。
- 所有草稿必须人工确认后才创建正式提醒。
- 确认后 App 会安排 iPhone 本地通知。

已修复一个关键体验问题：

- 后端提醒创建成功，但 iPhone 本地通知调度失败时，页面会退出确认页并提示“提醒已创建，但手机通知未安排”，避免用户误以为创建失败。

- 已接入药品库存 API。

- 家庭药品临期事项对所有成员可见，任一成员处理后共享状态同步更新。本阶段未接 APNs 家庭远程推送。

## 当前已知问题与建议优先级

### P0：不要泄露本地密钥

- `.env` 已被 Git 忽略。
- DeepSeek API Key 不能写入文档、日志、测试、截图或提交。
- 接手 AI 如果需要验证模型，应优先使用无个人信息测试句。

### P0：生产发布前移除登录页默认密码

当前登录页默认填充：

```text
13800138000 / Test-pass-2026
```

这是为了本地真机调试方便。正式发布前应改成：

- 仅 Debug/Profile 内测构建启用；或
- 通过 `--dart-define` 控制；或
- 完全移除。

推荐方式：

```text
--dart-define=PREFILL_TEST_LOGIN=true
```

不要让正式 release 包默认带测试账号密码。

### P1：把“模型不可用”原因拆细

当前 App 显示：

```text
本地规则（模型不可用）
```

但真实原因可能是：

- 未配置 API Key
- SSL 证书错误
- 模型网络超时
- 模型返回格式不合规
- 模型拒绝或服务端错误

建议后端返回更细的错误码，App 展示更可操作的说明。

### P1：测试环境不要被本地 `.env` 污染

目前 `settings.py` 会自动加载仓库根目录 `.env`。这对开发方便，但会污染 pytest。

建议增加测试专用开关，例如：

```text
DJANGO_SKIP_DOTENV=true
```

或者在 `pytest.ini` / `conftest.py` 中统一覆盖缓存与 ASR 相关环境变量。

### P1：服务器域名恢复后做线上回归

备案/域名恢复后，需要重新验证：

- `https://aipupu.cloud/api/v1/health`
- `https://files.aipupu.cloud/`
- 登录、刷新、退出
- 文字提醒模型兜底
- OCR 上传、识别、确认
- FunASR 语音识别
- Nginx、证书续期、备份、回滚

### P1：语音识别体验与容量

本机真实链路已打通，后续优化建议：

- 增加能力检测文案，区分“服务未启动”“服务忙”“网络错误”“权限拒绝”
- 真机录音链路做端到端测试
- 保持“识别只填入文字，不自动创建提醒”的安全边界

### P2：工作流智能化

未来 B+C 路线建议：

- 模型映射到注册工作流模板已经完成，后续可扩展更多模板
- 所有执行动作仍由固定组件完成
- 新类型首次确认，可信后可自动创建同类提醒
- 天气、交通、节假日、票务、信用卡还款等作为可验证 Provider 接入

## 交接提醒

- 不要把这个项目继续做成无限权限的“全能助手”。当前产品更稳的方向是“提醒和生活工作流助手”。
- 模型只负责理解和组装，执行必须通过已验证组件。
- 用户非常重视真机验证、服务器验证和 GitHub 状态实证，不要只说“应该可以”。
- 所有 Markdown 文件写中文。
- 对外部服务、密钥、个人日程文本要保守处理。
